# 사용자 시나리오 — Stamp Up

버전: v1.1 (작성일: 2026-08-13, v1.0→v1.1: 게임형 미션/리워드 시나리오 문구를 일반 스탬프 적립/쿠폰 서비스 톤으로 갱신)
근거 문서: `docs/1-domain-definition.md` (v1.6), `docs/3-PRD.md` (v1.5)

## 액터
- 거래처 담당자 A (role=CUSTOMER)
- 관리자 B (role=ADMIN)

---

## 1. 회원가입 (거래처 담당자)

**전제**: 거래처 담당자 A가 서비스를 처음 이용하며, 아직 계정이 없다.

1. A가 회원가입 화면에서 이메일, 비밀번호, 이름을 입력한다.
2. 시스템이 이메일 중복 여부를 검증한다.
3. 중복이 없으면 role=CUSTOMER 계정이 생성된다.
4. 회원가입이 완료되고 로그인 화면으로 이동한다.

**결과**: A는 CUSTOMER 계정으로 로그인할 수 있게 된다.

---

## 2. 로그인 / 로그아웃 (거래처 담당자)

**전제**: A가 회원가입을 마쳤다.

1. A가 로그인 화면에서 이메일/비밀번호를 입력한다.
2. 시스템이 인증에 성공하면 access token과 refresh token을 발급한다.
3. A가 스탬프 홈 화면으로 이동하여 서비스를 이용한다.
4. A가 로그아웃 버튼을 누른다.
5. 서버에 저장된 refresh token이 폐기되고, 클라이언트의 토큰이 삭제된다.
6. 로그인 화면으로 이동하며, 이후 인증이 필요한 화면 접근 시 로그인 화면으로 리다이렉트된다.

**결과**: A는 정상적으로 로그인/로그아웃을 수행한다.

---

## 3. 스탬프 적립 안내 확인 및 적립 요청 (거래처 담당자)

**전제**: A가 로그인한 상태이며, 관리자 B가 등록한 진행중 적립 항목이 존재한다.

1. A가 스탬프 적립 안내 화면에서 진행중/예정 적립 항목 목록과 참여 여부를 확인한다.
2. A가 진행중인 적립 항목 하나를 선택해 상세 화면(설명, 진행기간, 적립조건, 지급 스탬프/수량)을 확인한다.
3. A가 적립 요청 버튼을 누른다.
4. 시스템이 (미션, A) 조합의 MissionParticipation을 상태 JOINED로 생성한다.
5. A가 "적립 진행 현황" 화면에서 해당 항목이 직원 확인 대기 목록에 표시되는 것을 확인한다.

**결과**: A는 해당 적립 항목에 참여중 상태가 된다.

---

## 4. 적립 확인 및 스탬프 적립 (거래처 담당자)

**전제**: A가 적립 항목에 참여중(JOINED) 상태이다.

1. A가 "적립 진행 현황" 화면에서 직원 확인 대기 중인 항목을 선택한다.
2. A가 테스트용 "확인 요청" 버튼을 누른다.
3. 시스템이 MissionParticipation 상태를 COMPLETED로 변경하고, 항목에 정의된 ingredientType 스탬프의 StampTransaction(적립, amount=stampCount)을 1건 생성한다.
4. A가 스탬프 및 이용 내역 화면에서 해당 스탬프 종류의 보유 개수가 증가한 것을 확인한다.
5. A가 이용 내역 화면에서 적립 이력(사유: 적립 확인, 일시)을 확인한다.

**결과**: A는 해당 스탬프를 획득하고, 적립 항목은 완료 목록으로 이동한다.

---

## 5. 쿠폰(혜택) 받기 (거래처 담당자)

**전제**: A가 혜택에 필요한 모든 스탬프를 필요 수량 이상 보유하고 있다 (예: 카레 = 양파 2 + 당근 1, A는 양파 3·당근 2 보유).

1. A가 쿠폰/혜택 목록 화면에서 받을 수 있는 혜택 목록과 각 혜택에 필요한 스탬프, 받을 수 있는지 여부를 확인한다.
2. A가 받을 수 있음으로 표시된 "카레"를 선택해 쿠폰 받기를 실행한다.
3. 시스템이 필요 스탬프에 명시된 종류(양파 2, 당근 1)만큼 StampTransaction(차감)을 각각 생성하고, RewardRedemption을 기록한다.
4. A의 스탬프 종류별 보유량이 즉시 차감된다 (양파 1개, 당근 1개 남음).
5. A가 "쿠폰 사용 내역" 화면에서 방금 받은 카레 내역을 확인한다.

**결과**: A는 스탬프를 소모하고 카레(쿠폰/혜택)를 받는다.

---

## 6. 마이페이지 (거래처 담당자)

**전제**: A가 로그인한 상태이다.

1. A가 마이페이지 화면으로 이동해 자신의 정보(이메일, 이름)를 확인한다.
2. A가 이름을 수정하고 저장한다.
3. A가 비밀번호 변경 화면에서 새 비밀번호를 입력해 변경한다.

**결과**: A의 정보와 비밀번호가 갱신된다.

---

## 7. 적립 항목 등록 및 상태 관리 (관리자)

**전제**: 관리자 B가 로그인한 상태이다.

1. B가 적립 항목 관리 화면에서 등록된 항목 목록(상태 포함)을 확인한다.
2. B가 "적립 항목 등록" 화면에서 항목명, 설명, 참여기간(시작/종료), 적립조건, 지급 스탬프 종류(ingredientType), 지급 수량(stampCount)을 입력해 저장한다.
3. 시스템이 참여기간 기준으로 항목 상태(예정/진행중/종료)를 자동 계산한다.
4. B가 필요 시 진행중인 항목을 수동으로 "종료" 처리한다 (참여기간이 남아 있어도 강제 종료되는 예외 처리).

**결과**: 신규 적립 항목이 등록되고, 거래처 담당자들이 조회·적립 요청할 수 있게 된다.

---

## 8. 적립 확인 처리 (관리자)

**전제**: 거래처 담당자 A가 적립 항목에 참여중(JOINED) 상태이다.

1. B가 적립 항목 관리 화면에서 해당 항목의 참여자 목록을 확인한다.
2. B가 A의 참여 건을 선택해 적립 확인 처리를 실행한다.
3. 시스템이 A의 확인 처리(고객 화면의 확인 요청과 동일 로직)를 수행하여 MissionParticipation을 COMPLETED로 변경하고 스탬프를 지급한다.

**결과**: A는 관리자 확인을 통해 적립을 완료하고 스탬프를 획득한다.

---

## 9. 혜택 등록 및 상태 관리 (관리자)

**전제**: 관리자 B가 로그인한 상태이다.

1. B가 혜택 관리 화면에서 등록된 혜택 목록을 확인한다.
2. B가 "혜택 등록" 화면에서 혜택명, 설명, 필요 스탬프([{ingredientType, quantity}])를 입력해 저장한다.
3. 시스템이 상태를 활성(ACTIVE)으로 생성한다.
4. B가 특정 혜택을 비활성(INACTIVE)으로 전환한다.

**결과**: 신규 혜택이 등록되어 거래처 담당자가 받을 수 있게 되며, 비활성화된 혜택은 신규로 받는 것이 불가능해진다.

---

## 10. [예외] 참여 기간 종료 후 신규 적립 요청 시도 (거래처 담당자)

**전제**: A가 조회 중인 적립 항목의 상태가 이미 "종료(ENDED)"이다.

1. A가 스탬프 적립 안내에서 종료된 항목을 선택해 상세 화면으로 이동한다.
2. 상세 화면에는 적립 요청 버튼이 비활성화되어 있거나, A가 요청을 시도해도 시스템이 요청을 거부한다.
3. 시스템은 "참여 기간이 종료된 항목입니다" 등의 사유로 신규 참여를 생성하지 않는다.

**결과**: A는 종료된 항목에 신규 적립 요청을 할 수 없으며, 기존 참여·완료 이력이 있다면 그것만 조회 가능하다.

---

## 11. [예외] 이미 완료한 적립 항목 재확인 시도 (거래처 담당자)

**전제**: A의 MissionParticipation이 이미 COMPLETED 상태이다.

1. A가 "적립 진행 현황"의 완료 목록에서 해당 항목을 다시 연다.
2. A가 확인 요청 버튼을 다시 누른다 (또는 중복 요청이 발생한다).
3. 시스템은 해당 (미션, A) 조합이 이미 COMPLETED임을 확인하고 재확인·재지급을 거부한다.

**결과**: 스탬프는 중복 지급되지 않으며, A의 보유 스탬프는 변하지 않는다.

---

## 12. [예외] 스탬프 부족 시 쿠폰 받기 시도 (거래처 담당자)

**전제**: A가 "카레"(양파 2 + 당근 1)에 필요한 스탬프 중 당근을 0개 보유하고 있다.

1. A가 쿠폰/혜택 목록 화면에서 "카레"를 확인하면 받을 수 없음 상태로 표시된다.
2. A가 쿠폰 받기를 시도한다.
3. 시스템은 필요 스탬프 중 하나라도 필요 수량 미만이면 요청을 거부한다 (일부 스탬프만 보유해서는 받을 수 없음).

**결과**: RewardRedemption과 StampTransaction(차감)이 생성되지 않으며, A의 스탬프는 그대로 유지된다.

---

## 13. [예외] 비활성 혜택 사용 시도 (거래처 담당자)

**전제**: 관리자 B가 "카레" 혜택을 비활성(INACTIVE) 상태로 전환했다.

1. A가 쿠폰/혜택 목록 화면에서 "카레"를 조회한다 (비활성 표시 또는 목록 미노출).
2. A가 필요 스탬프를 모두 보유하고 있음에도 쿠폰 받기를 시도한다.
3. 시스템은 혜택 상태가 비활성임을 확인하고 신규로 받는 것을 거부한다.

**결과**: 비활성 혜택은 받을 수 없다.

---

## 14. [예외] 이메일 중복 가입 시도 (거래처 담당자)

**전제**: 이미 특정 이메일로 가입된 계정이 존재한다.

1. 신규 사용자가 회원가입 화면에서 이미 사용 중인 이메일을 입력한다.
2. 시스템이 이메일 중복 여부를 검증한다.
3. 중복이 확인되어 "이미 가입된 이메일입니다" 등의 오류를 반환하고 계정을 생성하지 않는다.

**결과**: 동일 이메일로 중복 가입되지 않으며, 사용자는 다른 이메일로 재시도하거나 기존 계정으로 로그인해야 한다.
